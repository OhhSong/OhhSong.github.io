阿里云平台日常运维操作手册

归纳公有云上资源创建、扩容、快照回滚、网络与负载均衡等日常操作的通用路径。

2026年10月21日 7 分钟阅读 运维手册 阿里云云平台运维 云平台与公有云

一句话定位

这份手册只讲公有云上“日常要动手”的那部分事情：怎么开一台机器、怎么扩盘、怎么做快照和回滚、怎么开网络、怎么改负载均衡和数据库配置。涉及账号开通、费用结算、合同发票、内部审批的内容一律不在这里讨论，需要走各自的流程。

适用场景

  • 新业务上线，需要在云上开出一批标准化的云主机。
  • 生产主机磁盘使用率逼近阈值，需要在业务低峰期做容量补充。
  • 变更前需要留一份可回滚的快照，或误操作后需要按快照恢复磁盘。
  • 需要为新增的服务器之间、服务器与数据库之间开通网络互访。
  • 负载均衡新增监听端口、更换证书、调整转发策略。

资源模型与原理

公有云把资源按“地域 — 可用区 — 专有网络 — 交换机 — 实例”逐层收敛。地域决定物理位置和可用产品，可用区是地域内的独立故障域，跨可用区部署是性价比最高的一种高可用手段。专有网络划出私有地址空间，交换机把地址空间切给不同子网，安全组则挂在实例上做实例级访问控制——安全组只认源地址，管不了访问来自哪个省份，需要按区域收敛时必须靠网络侧的边界设备。

云盘与快照是“块设备 + 时间点副本”的关系：快照记录的是某个时刻磁盘块的状态，回滚会把整块盘退到那一刻，所以回滚前必须先对当前盘再打一份。负载均衡把前端监听映射到后端服务器组，证书挂在监听上；云数据库的白名单等价于实例级防火墙，不加就拿不到连接地址。

前置条件

  • 具备对应资源的操作权限，且操作已纳入变更窗口。
  • 明确目标地域、可用区、专有网络与交换机，避免资源开错网络。
  • 关键操作前完成快照，并确认快照进度为百分之百。
  • 命名规范统一：实例名、主机名、描述保持一致，便于定位。

操作步骤

1. 创建云主机

进入云服务器控制台创建实例。基础配置关注可用区、规格、镜像和磁盘类型；网络配置关注专有网络、交换机和安全组；系统配置关注登录凭证、实例名、主机名与描述。实例名与主机名建议完全一致，描述里写清业务与环境。确认订单前再核对一次规格与磁盘，避免开错后又要走变配。

2. 系统初始化

Linux 主机创建后先用控制台远程连接确认网络，再核对监听端口，随后按需调整远程登录端口并重启 SSH 服务。

ip -4 addr show
ss -ntlup
vi /etc/ssh/sshd_config     # 修改 Port 与允许登录的用户
systemctl restart sshd
ss -ntlup | grep sshd

Windows 主机用镜像自带的初始化工具做一次封装，重启后确认远程桌面可达。自带防护软件是否保留按统一基线决定，不在单台机器上开例外。

3. 安全组与互访

安全组规则分入方向和出方向，出方向通常放行全部，入方向只开必要端口。新增互访时按“源地址 + 协议 + 端口”三元组加规则，并在描述里写明用途与变更记录编号，方便日后清理。

# 示例：仅允许来自 192.0.2.0/24 的 3306 访问
# 控制台操作：安全组 - 配置规则 - 入方向 - 添加

禁止使用 0.0.0.0/0 敞开通用的管理端口；需要按区域收敛时，由网络侧边界设备负责，安全组只做端口粒度的收敛。

4. 磁盘扩容

生产主机优先采用“新增一块云盘”的方式扩容，在线即可完成，不触碰原有分区与文件系统。原盘扩容会改动分区表与文件系统，操作失误可能损失整盘数据，只在新建主机阶段推荐。

原盘扩容的标准顺序是：先做快照，再在控制台完成云盘扩容，最后进系统扩展分区与文件系统。

lsblk
df -Th
fdisk -lu /dev/vdb          # 确认分区表格式是否为 MBR
growpart /dev/vdb 1         # 扩展分区（GPT 场景参数一致）
xfs_growfs /data            # xfs 用这个；ext4 用 resize2fs /dev/vdb1
df -h

新增云盘则简单得多：挂载到目标目录，写入 fstab 时务必带 nofail，避免磁盘异常导致主机起不来。

5. 快照与回滚

自动快照策略适合做兜底：先建策略，再把一批云盘批量关联到策略上，最后在策略详情里核对关联盘数量是否与预期一致，数量对不上说明有盘漏挂。

临时快照用于变更前留档，命名建议“服务器名 + 变更记录编号 + 时间”，需要长期保留的在名称里标注保留期。回滚磁盘必须先停机，且回滚前对当前盘再做一份快照，保留期按七天到十五天设置。

6. 变配、换系统与回收

变更 CPU 内存、更换操作系统、回收实例都属于影响业务的操作。升级配置一般需要重启，降级配置需要先关机，所以先与业务方约时间。更换系统本质是重装，务必确认数据盘与系统盘的关系，不要把数据盘一并重置。

回收实例前先做永久快照，确认已关机、无业务访问后再释放。释放不可逆，公网地址与实例元数据都会随之消失。

7. 负载均衡

新增监听时按四段配置推进：协议与监听（端口、调度算法、会话保持、访问控制）、证书（HTTPS 必须挂证书并选安全策略）、后端服务器组、健康检查。变更监听协议需要先删旧监听再建新监听，删除前把原配置截图存档，事后逐项比对新旧差异再通知业务验证。

变更前端端口号时更稳妥的做法是“先加后删”：新增监听端口、保留旧端口，业务验证通过后再停用并删除旧监听。更换证书支持直接替换，替换窗口内新旧证书可能并存，务必在低峰操作。

8. 云数据库

白名单分组按“业务 + 变更记录编号 + 日期”命名，添加前先用搜索确认地址是否已在别的分组里，避免重复。修改参数前先确认该参数是否要求重启实例，这一步要在变更评审阶段就写清楚；提交参数后由业务侧验证。

扩容存储空间后不可回退，云盘类型的规格变更通常对业务无感，本地盘类型会有闪断。变更实例规格的耗时与负载、库表数量相关，连接会出现短时中断，应用侧必须具备重连能力。主实例磁盘不应小于只读实例。

9. 对象存储与域名

创建存储桶时关注地域、存储类型、读写权限、版本控制与服务端加密。生产桶默认私有读写，日志转存单独开启。生命周期规则用于成本治理，比如临时转储目录按十五天过期删除。负载均衡上的证书改完后，同步检查 Web 应用防火墙侧的站点证书。

域名侧常见操作是新增二级域名、修改解析记录值。解析生效受 TTL 影响，变更前把 TTL 调小，切完再调回。

验证

  • 主机开机后用控制台远程连接确认登录、时区、主机名、磁盘挂载与预期一致。
  • 安全组改动后用 telnet 或 nc 从另一台机器验证目标端口连通性。
  • 扩容后 df -h 与 lsblk 的容量同时变化，且业务写入正常。
  • 快照在快照列表中显示为百分之百完成，且可点开查看详情。
  • 负载均衡监听状态为运行中，后端健康检查正常，业务域名访问返回预期状态码。
  • 数据库变配完成后确认连接地址未变、参数已生效、监控无异常抖动。

风险与回滚

操作影响回滚手段
云盘在线扩容分区与文件系统变更，误操作可能丢数据变更前的快照回滚
磁盘回滚数据退回到快照时刻回滚前再打快照，可二次回滚
更换操作系统系统盘被重置保留系统盘快照，重新挂载数据盘
实例规格变更重启或短时中断变回原规格，注意需要再次重启
数据库规格变更连接闪断变回原规格，业务侧重连
负载均衡删监听该端口业务中断按截图存档重建监听

原则只有一条：所有不可逆动作之前，先有一份可回滚的时间点副本。

常见问题

新机器连不上。 先看安全组入方向是否放行，再看实例内防火墙与监听地址，最后确认是否绑定了公网地址或走了跳板。

扩容后 df -h 容量没变。 控制台只是扩大了块设备，还需要在系统内扩展分区和文件系统。

快照显示已完成但回滚失败。 检查实例是否已完全关机，以及该盘是否被其他实例挂载。

数据库连不上。 白名单没加、用了公网而非私网地址、账号未授权，按这三项依次排查。

负载均衡后端全部不健康。 健康检查端口与路径是否与后端一致，安全组是否放行了来自负载均衡网段的探测流量。
