vSAN 磁盘故障处理与组件重建

vSAN 6.7 与 7.0 的故障盘判定、磁盘组移除、组件重建与验证流程。

2026年10月21日 5 分钟阅读 运维手册 VMwarevSAN存储 虚拟化与超融合

一句话定位

vSAN 的可用性靠副本与重建，不靠单块盘——故障处理的核心是先判清是容量盘还是缓存盘、还有没有可落位的故障域余量，再决定移除单盘还是整个磁盘组。

适用场景

  • 磁盘组内磁盘状态为 Failed、Degraded 或 Inaccessible；
  • 磁盘已损坏，无法通过界面正常移除；
  • 更换磁盘后需要重新声明磁盘组并触发组件重建；
  • 重建长期无进展，需要定位是容量、网络还是策略问题；
  • 平台从 6.7 升级到 7.0 前，需要确认两版处置方式的差异。

前置条件

  1. 版本确认：管理 → vSAN → 配置，确认集群版本。6.7 只能整组移除磁盘组，7.0 支持单独移除容量盘，两者操作不可混用。
  2. SSH 与权限：在主机管理 → 服务中开启 SSH，使用具备 vSAN 管理权限的账号。
  3. 数据保护：关键虚拟机完成备份，或确认存储策略的副本数足以承受单盘、单主机故障。
  4. 容量余量：集群剩余容量足以承载重建期间的副本落位；剩余空间低于两成时先扩容再动手。
  5. 备件合规：替换磁盘在 vSAN 兼容性列表内，容量不小于原盘，缓存盘与容量盘的介质类型符合原设计。
  6. 窗口与通知：重建会持续占用 IO 与网络，安排在业务低峰执行，并提前告知业务方。

操作步骤

第一步：判定故障盘与影响范围

ssh root@192.0.2.10

# 列出 vSAN 磁盘，筛出异常状态
esxcli vsan storage list | grep -i -E "failed|degraded|inaccessible"

# 查看磁盘组与缓存盘、容量盘的对应关系
esxcli vsan storage list

记录故障盘的设备名或 UUID。容量盘故障影响的是该盘上的组件，集群会按策略在其他主机重建；缓存盘故障会让整个磁盘组不可用，影响面明显更大。

第二步：尝试用维护模式迁走组件

在 vSphere Client 中对故障盘所在主机执行进入维护模式，选择“确保所有组件可访问”。迁移成功说明副本仍能落位，后续按正常流程换盘即可；迁移失败要记录错误码，常见两类是无可用副本（对象不可访问）与容量不足。

# 命令行方式进入维护模式
esxcli system maintenanceMode set --enable true

# 确认主机已进入维护模式
vim-cmd hostsvc/hostsummary | grep -i maintenance

第三步：关闭自动磁盘管理并移除

自动磁盘管理开启时，拔盘与重建可能被自动动作打断，先关掉再操作：

esxcli vsan storage automode set --enabled false

vSAN 6.7 的做法是移除整个磁盘组，用磁盘组 UUID 定位：

# 查到磁盘组 UUID 后整组移除
esxcli vsan storage remove -u $VSAN_DISKGROUP_UUID

# 确认移除结果
esxcli vsan storage list

vSAN 7.0 在仅容量盘故障时可以单盘移除；缓存盘故障或启用了去重压缩时，仍需整组移除：

# 单盘移除，参数为设备 ID
esxcli vsan storage remove -d $VSAN_DEVICE_ID

# 整组移除，参数为磁盘组 UUID
esxcli vsan storage remove -u $VSAN_DISKGROUP_UUID

第四步：退出维护模式并触发重建

换盘完成后退出维护模式，确认主机重新加入集群，再触发重平衡让组件尽快按策略落位：

esxcli system maintenanceMode set --enable false

# 触发主动重平衡，加快数据重建与分布
esxcli vsan proactive rebalance start

# 查看同步进度
esxcli vsan debug resync status

# 查看集群健康
esxcli vsan health cluster get

新盘需要重新声明后才能被 vSAN 使用，按介质类型加入对应磁盘组：

# 先列出可用设备，确认设备名与介质类型
esxcli vsan storage list

# 将新盘加入磁盘组，缓存盘与容量盘参数不同，按实际填写
esxcli vsan storage add -d <设备名> -s <缓存设备名>

第五步：监控重建直至收敛

重建期间重点看三个指标：组件同步进度、集群剩余容量、集群健康告警。对象多、数据量大时重建可能持续数小时到数天，期间不要再次拔盘，也不要对同一集群做升级或策略变更。

验证

  1. esxcli vsan storage list 中故障盘或故障磁盘组已消失，新盘状态正常；
  2. esxcli vsan debug resync status 显示同步完成，无长期滞留对象；
  3. esxcli vsan health cluster get 各项为 Healthy，无组件缺失告警；
  4. 集群容量回到安全水位，存储策略的合规性检查通过；
  5. 抽测虚拟机可正常读写，业务侧无感知异常。

风险与回滚

  • 移除不可逆：磁盘组移除后元数据清空，数据只能靠其他主机副本重建；操作前必须确认副本数与故障域余量足够。
  • 无副本可重建：策略副本不足或故障域设置过窄时，重建会卡在无落点，需先把集群恢复为可访问状态再处理。
  • 去重压缩：启用去重或压缩的集群不支持单盘移除，必须先走整组移除，并提前评估关闭策略的影响。
  • 重建期性能：重建占用带宽与磁盘 IO，业务敏感集群建议限制并发或错峰执行。
  • 回滚思路：若移除后发现判断错误，不要尝试手工拼回磁盘组，应停止操作、保留现场，通过备份恢复受影响的虚拟机。

常见问题

Q：磁盘状态卡住，移除命令一直不返回。 先确认主机确实在维护模式、自动磁盘管理已关闭；仍卡住时可强制把盘标记为丢失并重新扫描适配器，再重试移除。

Q：组件长时间不重建。 多为容量不足、副本策略不允许落位或主机间网络异常。先看剩余容量与策略合规性，再查 vSAN 网络连通性。

Q：7.0 上单盘移除后集群仍告警。 确认移除的是容量盘而非缓存盘；缓存盘故障必须整组移除，残留的磁盘组元数据会持续产生告警。

Q：换盘后新盘不被识别。 核对设备是否在兼容列表、是否被 RAID 卡以直通模式呈现；必要时重新扫描存储适配器后再执行声明命令。

Q：重建期间业务变慢。 这是预期内的资源竞争。可在窗口内降低并发同步数、暂停非关键批量任务，避免在重建高峰期做其他变更。
