麒麟 V10 SP3 安全基线核查清单

按初始化、SSH、审计、权限与口令五组，整理麒麟 V10 SP3 2403 的核查项与整改命令。

2026年10月21日 11 分钟阅读 运维手册 麒麟安全基线Linux 操作系统与安全基线

一句话定位

安全基线不是交差的表格，而是能落进脚本、能被复查、也能退回的开关。麒麟 V10 SP3 2403 的条目不难，难的是顺序：先定形态，再收服务面，然后补审计留痕，最后动口令权限。顺序反了，容易在改 SSH 或认证栈时把自己锁在门外。

适用场景

  • 新装麒麟 V10 SP3 2403 服务器上线前的初始化加固；
  • 存量节点等保、合规审计后的集中整改；
  • 批量下发基线脚本前逐项比对并确认例外；
  • 从 CentOS 迁移到麒麟，核对同名配置文件的路径与取值差异。

数据库专用机、容器宿主机等特殊节点要按业务裁剪，基线是下限，不是模板。

前置条件

  • 已完成最小化安装，根分区建议用 LVM 便于打快照；
  • 内网软件源可用，能安装审计与访问控制相关包；
  • 保留 root 本地控制台会话，或确认带外管理通道可用；
  • 有变更窗口，审计规则与内核参数需重启才完全生效；
  • 变更前统一备份配置，下文改动都假定有回退文件。

操作步骤

第一步：安装形态与软件源

最小化安装减少默认账号、组件与监听端口，后续检查成本更低。装完先确认版本与分区，根目录留足余量，避免审计日志写满：

cat /etc/kylin-release
df -hT

内网源按实际仓库地址改写，改前留备份：

cd /etc/yum.repos.d
cp -a kylin_x86_64.repo kylin_x86_64.repo.bak
sed -i 's#^baseurl=.*#baseurl=http://192.0.2.10/kylin/V10SP3-2403/os/$basearch/#' kylin_x86_64.repo
grep -nE 'baseurl|gpgcheck' kylin_x86_64.repo

关闭签名校验能让不可签名的内网源工作，但源被篡改时无从发现。只有镜像由可信渠道同步、网络侧也限制来源时，才登记为例外；能维护签名就别关。

第二步：网络与服务面

基线关闭并禁用防火墙，前提是上游有边界过滤且主机不直接暴露公网。不成立就保留防火墙、只放行必要端口，并在基线记录里写明偏差。

systemctl stop firewalld
systemctl disable firewalld
systemctl is-active firewalld

关闭多 IP 绑定，避免一条解析记录带来多个地址；打开可疑包记录，把源地址不可路由的包写进内核日志，便于发现扫描与欺骗。后者抬高日志量，需配合轮转与容量告警：

grep multi /etc/host.conf
echo 'multi off' >> /etc/host.conf
sysctl -w net.ipv4.conf.all.log_martians=1
printf '%s\n' 'net.ipv4.conf.all.log_martians=1' >> /etc/sysctl.conf

传输工具按需安装，lrzsz、net-tools 装机即用；telnet 与 ftp 是明文协议，只在隔离网段临时排障，用完停服。确需 FTP 时用 chroot 限制目录，但 allow_writeable_chroot 会削弱隔离，能用 SFTP 就不用 FTP。

第三步：SSH 与登录入口

改前备份，把端口、日志级别与尝试次数一次改到位：

S=/etc/ssh/sshd_config
cp -a $S $S.bak
sed -i 's/^#\?LogLevel.*/LogLevel INFO/' $S
sed -i 's/^#\?MaxAuthTries.*/MaxAuthTries 4/' $S
sed -i 's/^#\?Port .*/Port 42222/' $S
sshd -t && systemctl restart sshd

注意：SSH 对同一参数取首次出现的值，残留旧行会让新值失效，验证要看 sshd -T 而不是只看文件；改端口前确认防火墙与安全组已放通，并保留一个已登录会话。

登录横幅写清行为会被监控，既是合规项也起警示作用：

printf '%s\n' 'Login success. All activity is monitored and recorded.' > /etc/motd
chmod 644 /etc/motd

HostKeyAlgorithms 基线倾向注释掉，不强制指定主机密钥算法：兼容性好，老客户端不会握手失败，代价是可协商算法变宽。客户端可控时建议保留强限定。

第四步：sudo 日志与命令留痕

sudo 的两项配置是审计基础：提权写进独立日志，强制经由伪终端执行，避免命令绕过会话记录。改 /etc/sudoers 前先 visudo -c 校验，加入：

Defaults logfile=/var/log/sudo.log
Defaults use_pty

再让日志服务把 local2.debug 写入同一文件。命令留痕依托历史记录参数与一个独立追加文件：

cat >> /etc/profile <<'EOF'
HISTSIZE=100
HISTTIMEFORMAT="%F %T %u "
export HISTORY_FILE=/var/log/useraudit.log
export PROMPT_COMMAND='printf "%s %s %s\n" "$(date "+%F %T")" "$(who am i)" "$(history 1)" >> "$HISTORY_FILE"'
EOF

该文件对所有登录用户可写，基线通常放到 666，等于谁都能改自己的历史记录，这是”可追溯优先于不可篡改”的取舍。有条件时改用只追加属性或把记录送往集中平台。

第五步：审计

审计分三层：内核参数保证默认开启，规则文件定义记录什么，存储阈值决定写满后怎么办。先确认引导参数：

cat /proc/cmdline
find /boot -name grub.cfg

在 UEFI 引导配置的内核行补 audit=1，与相邻参数留空格；再设 auditd 自启并重启：

systemctl enable auditd
systemctl is-enabled auditd
auditctl -l
reboot

规则按类别拆文件，下面以模块、账号、时间三类为例；文件删除与网络环境变更按同样方式补上，删除事件记得带 auid>=1000 过滤：

cat > /etc/audit/rules.d/10-kmod.rules <<'EOF'
-w /sbin/insmod -p x -k kmod
-w /sbin/rmmod -p x -k kmod
-w /sbin/modprobe -p x -k kmod
-a always,exit -F arch=b64 -S init_module -S delete_module -k kmod
EOF

cat > /etc/audit/rules.d/20-account.rules <<'EOF'
-w /etc/passwd -p wa -k account
-w /etc/shadow -p wa -k account
-w /etc/group -p wa -k account
-w /etc/gshadow -p wa -k account
-w /etc/security/opasswd -p wa -k account
EOF

cat > /etc/audit/rules.d/30-clock.rules <<'EOF'
-a always,exit -F arch=b64 -S settimeofday -S adjtimex -S clock_settime -k clock
-w /etc/localtime -p wa -k clock
EOF

删除事件带 auid>=1000 可减少系统进程噪声；网络变更要覆盖主机名、域名与解析文件。64 位系统上 arch=b32 的规则不要删，兼容性靠它兜底。规则写完重启 auditd 生效。

存储阈值按审计分区容量的四分之一估算，换算成 MB 写入配置：

df -h /var/log/audit
grep -w space_left /etc/audit/auditd.conf

例如 500 GB 分区取 128000 左右。阈值过低频繁告警，过高丢日志；space_left_action 用告警而非关机。进程记账用 psacct 补足，lastcomm 能看到执行记录。安全事件日志单独归档：

cat >> /etc/rsyslog.conf <<'EOF'
*.err /var/adm/messages
kern.debug /var/adm/messages
daemon.notice /var/adm/messages
EOF
systemctl restart rsyslog

内核调试级日志量很大，上线前必须配好轮转与容量告警。

第六步：系统设置与 SELinux

这一组改动都短，影响很直接：

sed -i '$ a\TMOUT=1800' /etc/profile
sed -i '$ a\* hard maxlogins 10' /etc/security/limits.conf
sed -i '$ a\umask 027' /etc/sysconfig/init
printf 'kernel.core_pattern=|/bin/false\n' >> /etc/sysctl.conf
echo 0 > /proc/sys/kernel/ctrl-alt-del
printf 'CtrlAltDelBurstAction=none\n' >> /etc/systemd/system.conf
systemctl daemon-reexec && sysctl -p

关闭 core dump 是因为转储文件可能含内存里的凭据；禁用组合键重启是防误触导致业务中断。时间同步建议用 chrony，沿用 ntpdate 时十分钟一次，源地址按环境替换：

echo '*/10 * * * * /usr/sbin/ntpdate 192.0.2.10' | crontab -
crontab -l

SELinux 用 permissive 而不是 disabled：不影响业务，又保留拒绝记录。改引导参数、改配置、重打标签三步缺一不可，首次重打标签的重启会明显变慢，要预留窗口：

grep SELINUX /etc/selinux/config
touch /.autorelabel
reboot
getenforce

第七步：文件权限

启动目录只允许属主写，防止普通用户替换服务单元；重要文件按最小可用原则收权限：

chmod -R 744 /etc/systemd/system /etc/systemd/user /etc/systemd/network
chmod 750 /etc/rc.d/init.d /etc/rc0.d /etc/rc1.d /etc/rc2.d /etc/rc5.d /etc/rc6.d
chmod 644 /etc/passwd /etc/group /etc/services
chmod 600 /etc/shadow /etc/xinetd.conf /boot/efi/EFI/kylin/grub.cfg

/etc/security 在基线里常被写成 600，照抄文件权限会出问题：目录去掉执行位后连 cd 都进不去，认证会异常。目录取 700 或 750，600 只留给目录里的文件，偏差写进说明。

日志侧要求组不可写执行、其他无权限，并固定新建日志的默认模式：

find /var/log -type f -perm /027
find /var/log -type f -exec chmod g-wx,o-rwx {} +
grep -nE 'FileCreateMode|DirCreateMode' /etc/rsyslog.conf

在 rsyslog.conf 中设 $FileCreateMode 0640、$DirCreateMode 0755，否则新日志又回到宽松权限。留痕文件会被上面的 find 命中，属已知例外，在检查脚本里显式排除。

第八步：口令与账号

口令复杂度靠质量模块，长度、字符类、字典与相似性检查一起配，对 root 同样生效：

P=/etc/security/pwquality.conf
sed -i 's/^#\?minlen.*/minlen = 12/' $P
sed -i 's/^#\?minclass.*/minclass = 4/' $P
sed -i '$ a\dictcheck = 1' $P
sed -i '$ a\usercheck = 1' $P
sed -i '$ a\palindromic' $P

再在认证栈的 pam_pwquality 行追加 enforce_for_root，让 root 改密同样受控。失败锁定取 5 次、900 秒，既挡暴力破解，又不会把敲错口令的人锁太久。同源认证栈必须同步改，否则不同入口两套策略；锁定状态用 faillock --user 查看。账号侧清理默认账号、服务账号设不可登录；只读入口建议单建普通账号并授最小 sudo，比再造 uid 0 账号安全——重复超级用户会让审计难分辨操作者。

第九步：维护模式与别名

别名文件中除 postmaster: root 外的 root 别名应注释，避免邮件落到别处。限制维护模式是双刃剑：注释救援项能防无认证进单用户，也切断本地急救通道，动手前必须确认带外管理可用并在测试机验证引导。

验证

逐条重跑上表命令，确认五件事：auditctl -l 能看到全部关键字且重启后仍在；getenforce 返回 permissive；sshd -T 的端口、日志级别、尝试次数与预期一致；find /var/log -type f -perm /027 为空（除登记例外）；普通账号实测 su 被拒、连错口令被锁。

风险与回滚

最大的风险依次是 SSH 把运维锁在门外、认证栈改错无法登录、引导配置改错无法启动。前两个靠备份、保留会话与带外通道兜底，第三个只能靠改前备份、改后先在控制台重启验证：

BK=/root/kylin-baseline-$(date +%F); mkdir -p $BK
cp -a /etc/ssh/sshd_config /etc/pam.d/system-auth /etc/pam.d/su \
     /etc/security/pwquality.conf /etc/selinux/config /etc/sysctl.conf \
     /etc/profile /etc/bashrc /etc/systemd/system.conf $BK/

回滚就是覆盖备份并重启服务，引导参数改动必须重启验证。SELinux 重打标签耗时长但别跳过，跳过会留下大量错误上下文，排查更麻烦。

常见问题

  • auditctl -l 是空的：规则文件没被加载，检查是否在 rules.d 下、属主是否 root，再重启 auditd。
  • 目录改成 600 后进不去：目录需要执行位才能遍历，600 只适用于文件，目录用 700 或 750。
  • 改完认证栈无法登录：用控制台恢复，覆盖备份后重启；改前一定留活跃 root 会话。
  • 口令策略对老账号无效：质量模块只在改密时校验，需配合强制改密周期。
