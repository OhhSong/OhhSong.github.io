RKE2 高可用集群离线部署

内网离线环境搭建 RKE2 高可用集群的完整流程，含私有仓库、控制面注册与入口负载均衡。

2026年10月21日 8 分钟阅读 运维手册 RKE2国产化集群部署 容器与云原生

一句话定位

在节点无法访问公网的内网环境里，用离线包从零搭起一套 RKE2 高可用集群，再把容器管理平台以固定域名暴露给使用者。

适用场景

  • 生产内网或专网，节点到公网镜像仓库不通。
  • 国产化操作系统上部署容器平台，需要按发行版调整安全策略与内核参数。
  • 单机版容器环境要升级成三节点控制面，消除单点。
  • 新机房或容灾分区复制一套标准集群底座。

前置条件

  • 角色规划：三台管理节点 node-01 至 node-03 同时承担控制面与 etcd，若干工作节点，两台入口负载均衡，一台跳板机负责分发文件与执行部署。
  • 操作系统已安装完成，root 可登录，磁盘按规划分好数据盘。
  • 离线物料齐全：安装脚本、镜像包与校验文件、平台 Helm Chart、私有仓库离线安装包。
  • 私有仓库可访问，所有节点都能连通 registry-a.example.com。
  • 平台域名已解析到负载均衡 VIP，证书与私钥已签发。
  • 各节点时间同步正常，偏差控制在秒级。

端口按最小必要开放：

端口用途开放范围
6443集群 API管理节点、跳板机、负载均衡
9345节点注册仅管理节点之间
2379–2380etcd 通信仅管理节点之间
10250kubelet集群内网
30080平台 Web 入口负载均衡节点
80/443对外域名业务网段

架构与原理

RKE2 把 etcd、控制面组件、kubelet 与容器运行时收进一个 systemd 服务，节点上不再单独跑 docker，少一层依赖。首个管理节点以 server 角色启动，自行拉起 etcd 并生成集群凭据；第二、第三个管理节点带着同一份凭据，通过 9345 端口注册进控制面，组成三副本 etcd。工作节点只跑 kubelet 与运行时，也可以交给平台侧按注册命令纳管。

离线部署的关键是断掉运行时的公网依赖。安装脚本与镜像包放固定目录，安装时把镜像导入内置的 containerd 镜像库；节点上的仓库配置文件再把上游地址重写到私有仓库。平台 Chart 与其中引用的镜像同样要提前推一份到私有仓库，安装时用统一仓库参数指过去，否则 Pod 会停在镜像拉取失败。

高可用分两层：控制面靠三台管理节点加 etcd 副本，入口靠两台负载均衡加 keepalived 漂移 VIP，nginx 把请求反代到各管理节点的 NodePort。

操作步骤

  1. 准备私有仓库。离线安装仓库服务，建好项目，按镜像清单把平台与业务镜像逐个推上去，推完在页面核对项目大小和标签数，缺一个都会在部署时卡住。

  2. 系统初始化，所有节点执行。关掉防火墙与安全策略，关闭交换分区，统一字符集。

systemctl disable --now firewalld
setenforce 0
sed -i 's/^SELINUX=enforcing$/SELINUX=disabled/' /etc/selinux/config
swapoff -a
sed -i '/ swap / s/^/# /' /etc/fstab
localectl set-locale LANG=en_US.UTF-8
  1. 加载内核模块。容器网络与转发依赖的几个模块要开机自动加载。
cat > /etc/modules-load.d/rke2.conf <<'EOF'
overlay
br_netfilter
veth
nf_conntrack
ip_tables
ip6_tables
EOF
systemctl restart systemd-modules-load.service
  1. 内核参数与句柄。写成一个独立文件，避免逐条追加到系统总配置里产生重复项。
cat > /etc/sysctl.d/90-rke2.conf <<'EOF'
net.ipv4.ip_forward=1
net.bridge.bridge-nf-call-iptables=1
net.bridge.bridge-nf-call-ip6tables=1
vm.swappiness=0
vm.max_map_count=262144
fs.file-max=2097152
fs.inotify.max_user_watches=524288
EOF
sysctl --system

cat >> /etc/security/limits.conf <<'EOF'
* soft nofile 655350
* hard nofile 655350
* soft nproc unlimited
* hard nproc unlimited
EOF

改完重启一次，让参数彻底生效。

  1. 数据盘与日志盘。集群状态、镜像、日志缓冲都放独立盘，根分区写满会直接拖垮控制面。
mkfs.xfs -f /dev/vdb
mkdir -p /var/lib/rancher
echo "UUID=$(blkid -s UUID -o value /dev/vdb) /var/lib/rancher xfs defaults 0 0" >> /etc/fstab
mount -a
df -hT /var/lib/rancher

日志盘同理挂到 /var/lib/rancher/fluentd/log，在工作节点上给出写权限。

  1. 网络接口与 bpffs。让 NetworkManager 忽略 CNI 创建的虚拟网卡，否则节点重启后网络插件可能接管失败。
cat > /etc/NetworkManager/conf.d/rke2-interface.conf <<'EOF'
[keyfile]
unmanaged-devices=interface-name:cali*;interface-name:flannel*;interface-name:cilium*
EOF
systemctl reload NetworkManager
mount bpffs /sys/fs/bpf -t bpf
echo 'bpffs /sys/fs/bpf bpf defaults 0 0' >> /etc/fstab
  1. 下发离线物料。镜像包放固定目录，安装脚本单独放一个工作目录，各节点路径保持一致。
mkdir -p /var/lib/rancher/rke2/agent/images /root/rke
# 镜像包与校验文件放入 images 目录，安装脚本放到 /root/rke/install.sh
ls -lh /var/lib/rancher/rke2/agent/images /root/rke

分发后核对各节点文件校验值，不一致的重传。

  1. 配置仓库重写，让上游地址全部指向本地仓库。
mirrors:
  docker.io:
    endpoint:
      - "https://registry-a.example.com"
  registry.k8s.io:
    endpoint:
      - "https://registry-a.example.com"
configs:
  "registry-a.example.com":
    tls:
      insecure_skip_verify: true

保存为 /etc/rancher/rke2/registries.yaml，权限设 600。仓库认证信息由部署脚本从凭据管理系统读取后写入同一文件，不进版本库，也不留在命令历史里。

  1. 首节点安装。写好集群凭据与证书备用域名后启动服务，等控制面组件全部起来再往下走。
cat > /etc/rancher/rke2/config.yaml <<'EOF'
token: "<cluster-token>"
tls-san:
  - "rancher.example.com"
  - "192.0.2.10"
  - "192.0.2.11"
  - "192.0.2.12"
EOF
export INSTALL_RKE2_ARTIFACT_PATH=/var/lib/rancher/rke2/agent/images
sh /root/rke/install.sh
systemctl enable --now rke2-server.service
journalctl -u rke2-server -f

补一次 PATH 与 kubectl 变量，后续排查会一直用到：

echo 'export PATH=$PATH:/var/lib/rancher/rke2/bin' >> ~/.bashrc
echo 'export KUBECONFIG=/etc/rancher/rke2/rke2.yaml' >> ~/.bashrc
source ~/.bashrc
kubectl get nodes
  1. 另两个管理节点注册。配置文件多一行 server 指向首节点的 9345 端口，其余保持一致。
cat > /etc/rancher/rke2/config.yaml <<'EOF'
server: "https://192.0.2.10:9345"
token: "<cluster-token>"
tls-san:
  - "rancher.example.com"
EOF
export INSTALL_RKE2_ARTIFACT_PATH=/var/lib/rancher/rke2/agent/images
sh /root/rke/install.sh
systemctl enable --now rke2-server.service
  1. 部署平台。Chart 与镜像都走私有仓库，审计日志落宿主机目录并限制保留天数。
export PLATFORM_HOST="rancher.example.com"
export REGISTRY="registry-a.example.com"
helm repo add platform https://charts.example.com/server-charts/stable
helm pull platform/platform --version 2.10.2
tar -xzvf platform-2.10.2.tgz
helm upgrade --install platform ./platform \
  --namespace cattle-system \
  --create-namespace \
  --set hostname="${PLATFORM_HOST}" \
  --set tls=external \
  --set auditLog.destination=hostPath \
  --set auditLog.level=3 \
  --set auditLog.maxAge=7 \
  --set systemDefaultRegistry="${REGISTRY}" \
  --set useBundledSystemChart=true

初始管理员口令不写进命令行，按平台的一次性初始化流程设置。

  1. 暴露平台入口。平台装完只有集群内地址，先在平台命名空间建一个 NodePort 类型服务，把 80 端口固定映射到 30080，负载均衡再指向这个端口。
apiVersion: v1
kind: Service
metadata:
  name: platform-nodeport
  namespace: cattle-system
spec:
  type: NodePort
  selector:
    app: platform
  ports:
    - port: 80
      targetPort: 80
      nodePort: 30080
      protocol: TCP
  1. 入口负载均衡。两台负载均衡装 nginx 与 keepalived，VIP 为 192.0.2.100，nginx 把域名反代到各管理节点的 NodePort。
upstream platform {
    server 192.0.2.10:30080 max_fails=3 fail_timeout=5s;
    server 192.0.2.11:30080 max_fails=3 fail_timeout=5s;
    server 192.0.2.12:30080 max_fails=3 fail_timeout=5s;
}
server {
    listen 443 ssl http2;
    server_name rancher.example.com;
    location / {
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_pass http://platform;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_read_timeout 900s;
    }
}

两份 keepalived 配置只差 state 与 priority，VIP 用同一地址；健康检查脚本探测本机 443 端口，连续失败三次就降权让出 VIP。

验证

kubectl get nodes -o wide
kubectl get pods -n kube-system
kubectl get pods -n cattle-system
kubectl -n kube-system get pods | grep -E 'etcd|kube-apiserver'
curl -sk -o /dev/null -w "%{http_code}\n" https://rancher.example.com/
ip a | grep -w 192.0.2.100
  • 三台管理节点均为 Ready，etcd 成员数为三。
  • 平台命名空间下的 Pod 全部 Running，重启次数稳定。
  • 域名与 VIP 都返回 200；手动停掉主负载均衡，VIP 在备用节点接管。
  • 随机重启一台工作节点，节点能自动回到集群并恢复调度。
  • 再拉一个新镜像，确认走的是私有仓库而不是公网。

风险与回滚

  • 镜像包不完整时安装会中途失败，节点留下半成品。重装前先清理 /var/lib/rancher/rke2 与对应 systemd 单元，再重新执行。
  • 控制面节点不能同时维护，一次只动一台，确认 etcd 成员健康后再动下一台。
  • 删集群会连带删业务数据，动手前确认上面没有仍在运行的工作负载，并留好备份。
  • 改完仓库配置要重启服务才生效，重启会短暂中断该节点上的容器，挑业务低峰做。
  • keepalived 的 VIP 与业务网段地址冲突会导致整段网络异常，上线前用 arping 探测一遍。
  • 数据盘没写进 fstab，重启后目录回到根分区，轻则磁盘告警重则控制面写满退出；恢复挂载后重启服务即可。
  • 回滚思路：保留旧版本 Chart 与旧 config.yaml，出问题时按原参数重装对应节点，不要在多节点上同时操作。

常见问题

现象常见原因处理思路
节点一直 NotReady网络插件未就绪或内核模块缺失查 kube-system 日志与模块加载
Pod 卡在 ImagePullBackOff仓库重写未生效或缺认证核对 registries.yaml 与仓库连通性
第二节点注册失败凭据或 server 地址不对，9345 不通核对配置文件与端口策略
etcd 只有两个成员第三节点注册后未同步完成查 etcd 日志与磁盘 IO
平台域名 502NodePort 不通或后端地址写错先在负载均衡上 curl 各节点端口
VIP 不漂移keepalived 未开机自启或脚本无执行权限检查服务状态与脚本权限
节点重启后丢数据盘fstab 未写或 UUID 写错用 blkid 核对后重写并 mount -a
