vSphere 平台证书轮换与备份存储清理

把 vCenter 业务证书重签、备份证书存储清理与主机批量续订串成一条可回退的操作链。

2026年10月21日 6 分钟阅读 运维手册 VMware证书虚拟化 虚拟化与超融合

一句话定位

vSphere 的证书问题，难点很少在“能不能续”，而在于“续完之后告警为什么还在”。一次完整的维护应当分成四段：先盘清到期面，再重签管理节点的业务证书，然后清掉备份存储里的历史残留，最后批量续订受管主机，收尾做交叉验证与告警复位。漏掉任何一段，都会留下反复告警的尾巴。

适用场景

  • vCenter Server Appliance 6.7 / 7.0 / 8.0 环境，证书由内置 VMCA 统一签发；
  • 巡检发现业务证书剩余有效期进入 30 天窗口，涉及的存储包括 vpxd、machine、vsphere-webclient 与 vpxd-extension；
  • 证书续期已完成，vCenter 仍持续报证书到期告警；
  • 受管主机数量较多，需要一次性批量续订主机证书。

若环境使用第三方 CA 签发证书，或处于链接模式且存在多个 PSC 节点，流程必须按厂商文档裁剪，不能直接套用下文。

前置条件

动手之前把下面几条确认到位，比事后回滚便宜得多：

  1. 快照：对每台待操作的 vCenter 虚拟机拍摄含内存快照，命名带日期，例如 cert-renewal-YYYYMMDD，描述里写清操作人与时间。这是唯一可靠的回滚手段。
  2. 账号与连通：root 可 SSH 登录设备，SSO 管理员可登录 vSphere Client，设备的 SSH 服务已开启。
  3. 资源与时间：根分区可用空间不低于 5GB；所有节点 NTP 同步正常。时间漂移会让证书校验出现很难解释的失败。
  4. 业务窗口：整体重置会重启全部组件，管理平面中断约 5 至 15 分钟，安排在业务低峰。
  5. 工具：批量续订依赖 PowerCLI，提前在工作站装好，并把无效证书处理策略设为忽略。

运行在链接模式下的环境，建议按“先关闭其余 PSC 节点、统一做快照、再逐个操作”的顺序推进，避免跨节点状态不一致。

操作步骤

第一步：盘点到期面

在任一 vCenter 上遍历全部证书存储，把每个条目的别名与到期时间打印出来：

VECS=/usr/lib/vmware-vmafd/bin/vecs-cli
for s in $($VECS store list); do
  echo "=== STORE: $s ==="
  $VECS entry list --store "$s" --text | egrep "Alias|Not After"
done

输出里重点看三类：业务证书存储、MACHINE_SSL_CERT、以及 BACKUP_STORE。STS 签名证书用厂商提供的检查脚本单独核对，它的有效期通常长得多，不必和业务证书混在一起处理。

按剩余天数排优先级：备份存储最急（到期即告警）、业务证书次之、主机证书再次之。

第二步：重签管理节点业务证书

这一步用设备自带的证书管理器走“重置全部证书”分支，由 VMCA 重新签发所有业务证书，有效期默认顺延两年，过程中会自动重启全部服务。

ssh root@vcenter-01          # 走完整域名时可写 vcenter-01.example.com
/usr/lib/vmware-vmca/bin/certificate-manager

进入菜单后按提示交互，真正需要判断的输入只有几条：

提示输入
是否使用配置文件生成证书Y
SSO 管理员口令按实际输入，终端不回显
IPAddress直接回车，留空
HostnamevCenter 的 FQDN，如 vcenter-01.example.com
VMCA Name与 Hostname 完全一致
两次 Continue operation均输入 Y

纯 IP 部署、没有 DNS 记录的环境，Hostname 一栏填管理地址即可，但要保证每次维护都保持同一套取值，不要在两种写法之间来回切换，否则证书主题会不一致。

执行期间不要断开 SSH，不要重启虚拟机，不要对虚拟机做快照或迁移。等到命令行重新回到提示符，说明整个重签流程结束。

第三步：清理备份证书存储

BACKUP_STORE 是每次证书更新时留下的历史副本。主证书续好了，这些旧副本到期依然会触发告警，必须显式删掉。清理动作只动历史备份，不影响在用证书，但操作前仍然建议留快照。

优先使用厂商提供的清理脚本，上传到 /tmp 后执行。若脚本在 Windows 上编辑过，先转换换行符，否则会报 bad interpreter：

cd /tmp && chmod +x clean_backup_stores.sh
sed -i -e 's/\r$//' clean_backup_stores.sh
./clean_backup_stores.sh
service-control --stop --all
service-control --start --all

拿不到脚本时就手动逐条删，思路是先列别名、再按别名删除：

VECS=/usr/lib/vmware-vmafd/bin/vecs-cli
$VECS entry list --store BACKUP_STORE --text | grep Alias
$VECS entry delete --store BACKUP_STORE --alias __MACHINE_CERT -y
for a in bkp_machine bkp_vpxd bkp_vsphere-webclient bkp_vpxd-extension; do
  $VECS entry delete --store BACKUP_STORE --alias "$a" -y
done

删完再列一次，确认没有临近到期的条目。服务重启约需 5 至 10 分钟，期间管理平面不可用，但宿主机上运行的虚拟机不受影响。

第四步：批量续订受管主机

图形界面适合几十台以内的规模：进入集群的“配置 → 系统 → 证书”，勾选目标主机，执行“续订证书”。vCenter 会通过 VMCA 逐台签发并下发，管理链路只中断秒级，主机不需要重启。

数量多时改用 PowerCLI，先连接、再逐个续订：

Connect-VIServer -Server vcenter-01.example.com -Credential (Get-Credential)

$targets = @('esxi-01','esxi-02','node-01')
foreach ($n in $targets) {
    $h = Get-VMHost -Name $n -ErrorAction SilentlyContinue
    if ($h) { $h | New-VMHostCertificate; Write-Host "renewed: $n" }
    else    { Write-Host "not found: $n" -ForegroundColor Red }
}

界面与脚本都失败时，才考虑登录单台主机重生成自签名证书——代价是该主机不再由 VMCA 统一签发，后续信任链要单独维护：

/sbin/generate-certificates
/etc/init.d/hostd restart
/etc/init.d/vpxa restart

完成后回到 vCenter，右键主机执行“连接”，重新建立信任关系。

验证

  1. 全量复查证书存储，确认 vpxd、machine、vsphere-webclient、vpxd-extension 四类条目的到期时间都已顺延到两年后；
  2. 复查 BACKUP_STORE，确认已无 30 天内到期的旧副本；
  3. 运行 STS 检查脚本，确认签名链完整、无过期节点；
  4. 逐台核对主机证书，剩余天数应回到 700 天以上；
  5. 登录 vSphere Client，在“系统管理 → 证书 → 证书管理”做一次目视确认；
  6. 到“监控 → 告警”筛选证书相关条目，逐条确认并重置为绿色，观察 24 小时不复现；
  7. 确认服务状态全部正常、虚拟机无异常中断，最后删除快照。

风险与回滚

主要风险集中在三处：整体重签期间管理平面不可用；服务启动失败导致 vCenter 无法登录；主机与 vCenter 的信任关系断裂。

回滚判据要提前写清楚，出现下列任一情况立即回滚：重签报错且服务起不来、SSO 认证失败、主机大面积断连、业务虚拟机出现异常。回滚动作就是恢复操作前的快照，等虚拟机重启完成后用 service-control --status --all 确认服务状态。恢复快照会一并丢掉快照之后的配置变更，但宿主机上的虚拟机数据不受影响。

主机侧的回滚成本很低：重启 hostd 与 vpxa 后重新连接即可；仍然不通时把主机移除后重新加入，前提是先置入维护模式。

常见问题

  • 证书管理器报无法连接 Lookup Service：先确认 STS 与 SSO 服务状态。STS 过期会连带阻塞业务证书重签，需要先单独处理签名证书。
  • 脚本报 bad interpreter: /bin/bash^M：换行符不兼容，用 sed -i -e 's/\r$//' 去掉行尾回车再执行。
  • 续期后告警还在：多数是 BACKUP_STORE 没清，或告警没手动复位，两件事都要做。
  • 个别 data-encipherment 证书始终不更新：该证书不走整体重置路径，需要按厂商专用脚本单独处理。
  • 服务启动失败：先看 /var/log/vmware/vmcad/certificate-manager.log 与 vmcad.log 定位原因，不要盲目重试。
