vSphere 日常运维与虚拟机全生命周期管理

覆盖虚拟机开通、变更、迁移与主机维护模式，把日常运维动作固化为流程。

2026年10月21日 6 分钟阅读 运维手册 VMwarevSphere运维 虚拟化与超融合

一句话定位

vSphere 的日常运维其实只落在两层：vCenter 负责编排与清单，ESXi 负责真正运行虚拟机，把这两层的常规动作固化成流程，八成的日常工单就不用再现场处理。

适用场景

  • 业务方申请新虚拟机，需要在既有集群内完成开通与交付；
  • 存量虚拟机扩容 CPU、内存、磁盘，或增加网卡、接入新的端口组；
  • 虚拟机需要在主机之间、数据存储之间迁移；
  • 物理服务器需要停机换件或升级，主机要进入维护模式；
  • 老物理机通过 P2V 收敛进虚拟化平台。

前置条件

  1. 账号与权限：日常操作使用运维角色，删除、迁移等高风险动作单独授权，不用管理员账号做日常登录。
  2. 连通性：vCenter 管理地址、ESXi 管理地址、目标端口组所在的二层网络均可达；跨网段操作走跳板机。
  3. 容量与资源：目标集群剩余 CPU、内存、存储满足新增或迁移需求，数据存储留出两成余量。
  4. 变更与备份：涉及关机的变更提前走流程；重要虚拟机在变更前拍快照或做备份，并明确快照只用于短时回退。
  5. 介质：操作系统 ISO 已上传到共享数据存储，VMware Tools 安装包可获取。

操作步骤

第一步：确认入口与基础信息

管理入口有两条：浏览器访问 vCenter 的 Web Client 做日常编排；单机故障时直连 ESXi 的 DCUI（控制台按 F2）处理网络与排障。主机侧先确认管理网络与服务状态：

# 在 ESXi 上查看管理网卡、IP 与路由
esxcli network ip interface list
esxcli network ip interface ipv4 get
esxcli network ip route ipv4 list

# vCenter 无法管理该主机时，重启管理代理
/etc/init.d/hostd restart
/etc/init.d/vpxa restart

# 查看主机概要，确认是否处于维护模式
vim-cmd hostsvc/hostsummary

DCUI 的 Troubleshooting 菜单同样提供 Restart Management Agents，效果等价，适合无法 SSH 时使用。

第二步：虚拟机开通与配置变更

新建虚拟机走标准向导：选择放置的主机与集群、数据存储、兼容性版本、客户机操作系统、CPU 与内存、磁盘与网卡，最后确认。显卡保持自动检测即可，除非有图形加速需求。批量场景用 PowerCLI 更稳：

Connect-VIServer -Server vcenter-01.example.com -User <account>

# 按模板批量开通
New-VM -Name app-01 -Template template-linux -VMHost esxi-01.example.com `
  -Datastore ds-a -ResourcePool cluster-a

# 变更规格前先确认电源状态
Get-VM -Name app-01 | Select-Object Name,PowerState,NumCpu,MemoryGB
Set-VM -VM app-01 -NumCpu 4 -MemoryGB 8 -Confirm:$false

# 增加一块 200GB 磁盘
New-HardDisk -VM app-01 -CapacityGB 200 -StorageFormat Thin

CPU 与内存的热添加依赖客户机操作系统与硬件版本，不满足时必须关机修改；磁盘与网卡可以在线添加，但客户机内还需扫描总线才能识别。

第三步：迁移、克隆与模板

迁移分两类：只换计算资源，或同时换存储。跨主机迁移依赖共享存储与 vMotion 网络；跨存储迁移本质是数据搬运，时长与磁盘已用大小成正比。克隆与模板是交付标准化的抓手：把装好基础软件与监控代理的虚拟机转成模板，后续开通直接从模板派生，避免每台重复配置。

# 迁移到指定主机与数据存储
Move-VM -VM app-01 -Destination esxi-02.example.com -Datastore ds-b

# 虚拟机转模板，或从模板派生新机
Set-VM -VM app-01 -ToTemplate -Confirm:$false
New-VM -Name app-02 -Template app-01 -VMHost esxi-01.example.com -Datastore ds-a

删除要区分两种语义：从清单移除只清理列表，磁盘文件仍留在数据存储上；从磁盘删除才会真正释放空间。生产环境先停止服务再删，删除前确认没有快照链和备份依赖。

第四步：主机维护模式

主机需要停机换件或升级时，先进入维护模式把负载迁走，再关电源。界面操作会先跑预检查，预检查不通过通常是某台虚拟机无法迁移（资源不足、光驱或设备占用、亲和性规则限制），逐条处理后再继续。数据迁移策略按场景选：

策略行为适用场景
迁移全部数据迁走虚拟机与全部文件换硬件、长时间停机
确保可访问性只迁可运行虚拟机的文件短时维护、补丁升级
不迁移数据原位保留主机内无运行负载
# 进入维护模式并自动迁出虚拟机
Set-VMHost -VMHost esxi-01.example.com -State Maintenance -Evacuate

# 维护完成后退出
Set-VMHost -VMHost esxi-01.example.com -State Connected

命令行侧可用 esxcli system maintenanceMode set --enable true，退出时置为 false。确认主机图标带维护标识后再执行关机，避免带负载断电。

第五步：P2V 收敛

物理机迁移用 Converter，Converter Server 可装在任意可达的 Windows 机器上，源端装有 Converter Agent 即可。在线转换选择 Powered-on machine，目标可以是 vCenter，也可以是单台 ESXi；转换完成后先断网启动核对驱动与磁盘布局，再切业务。Windows 源端需额外安装 Agent 组件，其余流程与 Linux 一致。

验证

  1. vCenter 近期任务全部为完成状态，无失败或部分成功；
  2. 虚拟机电源、Tools 状态与心跳正常，客户机内业务端口可访问；
  3. 迁移后核对虚拟机所在主机、数据存储与端口组是否符合预期；
  4. 主机退出维护模式后，集群内虚拟机分布均衡，无遗留告警；
  5. 扩容场景在客户机内确认新磁盘、新网卡已被识别并完成分区或绑定。

风险与回滚

  • 误删：清单删除与磁盘删除含义不同，删除前确认路径与备份；误删后从备份恢复，不要在原数据存储上继续写入。
  • 快照堆积：快照增长会撑爆数据存储，验证完成后及时合并删除，不把快照当备份。
  • 迁移中断：跨存储迁移中断可能留下残留文件，重试前清理目标端残留，避免空间被重复占用。
  • 维护模式卡住：预检查提示无法迁移时不要强行进入，先处理占用设备或调整资源，必要时临时关闭非关键虚拟机。
  • 回滚：配置类变更记录变更前参数；涉及关机的变更保留快照并约定回滚时限，超时后合并快照。

常见问题

Q：vCenter 显示主机断开，但主机本身能 ping 通。 先看主机管理代理状态，重启 hostd 与 vpxa；再核对主机时间与证书是否过期，时间偏差过大会导致握手失败。

Q：虚拟机迁移进度长时间停在某个百分比。 多为源或目标存储压力过大，或 vMotion 网络带宽不足。暂停其他批量任务，确认网络无丢包后重试。

Q：控制台挂载 ISO 后客户机看不到光驱。 检查 CD/DVD 设备是否勾选“电源接通时连接”，并确认 ISO 所在数据存储对该主机可见。

Q：模板派生出的虚拟机网络不通。 模板里可能残留旧网卡配置或 MAC 绑定，检查客户机内配置文件与端口组 VLAN 是否一致。
