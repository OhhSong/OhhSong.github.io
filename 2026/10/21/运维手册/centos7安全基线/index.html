CentOS 7 安全基线核查与落地清单

按初始化、审计、日志、SSH、口令与账号五类，整理 CentOS 7 基线的核查项与整改命令。

2026年10月21日 9 分钟阅读 运维手册 CentOS安全基线Linux 操作系统与安全基线

一句话定位

安全基线不该是一张用来应付检查的表格，而应该是一组能落进脚本里的开关。本文按“先收紧内核与服务面、再补齐审计、最后管住登录入口”的顺序，把 CentOS 7 最小化安装后最常见的整改项整理成可核查、可回退的清单。

适用场景

  • 新建 CentOS 7.x 服务器上线前的初始化加固；
  • 存量服务器的合规审计整改；
  • 批量下发基线脚本前的逐项核对与差异确认；
  • 从其他发行版迁移过来，需要对齐同类要求。

容器宿主机、数据库专用机等特殊用途节点，部分条目要按业务实际裁剪，不要照抄。

操作步骤

改动之前先做文件备份，逐条都可回退：

BK=/root/baseline-bak-$(date +%Y%m%d%H%M%S); mkdir -p $BK
for f in /etc/init.d /etc/ssh/sshd_config /etc/selinux/config /etc/profile \
         /etc/bashrc /etc/audit/rules.d/audit.rules /etc/security/pwquality.conf; do
  cp -a "$f" "$BK"/ 2>/dev/null
done

第一步：收紧启动与内核面

限制普通用户对启动脚本目录的写权限，并把地址空间随机化开到较高等级：

chmod -R 744 /etc/systemd/system
chmod -R 744 /etc/systemd/user
sysctl -w kernel.randomize_va_space=2

SELinux 建议保持 permissive 而不是 disabled：既不影响业务，又能留下拒绝记录用于后续排查。

sed -i -e '/SELINUX=/ s/^/#/' /etc/selinux/config
sed -i '$ a\ SELINUX=permissive' /etc/selinux/config

第二步：收敛服务与网络参数

邮件服务只处理本地投递，不要对外监听；主机不承担路由职责，因此关闭 ICMP 重定向；同时打开可疑包记录，便于日志侧发现异常源地址。

sed -i -e '/inet_interfaces/ s/^/#/' /etc/postfix/main.cf
sed -i '$ a\ inet_interfaces = loopback-only' /etc/postfix/main.cf

sysctl -w net.ipv4.conf.all.send_redirects=0
sysctl -w net.ipv4.conf.default.send_redirects=0
sysctl -w net.ipv4.conf.all.log_martians=1
sysctl -w net.ipv4.conf.default.log_martians=1
sysctl -w net.ipv4.route.flush=1

要让参数在重启后仍生效，需要把同样的键值追加到 /etc/sysctl.conf。最小化安装通常没有邮件服务，对应段落跳过即可。

第三步：补齐审计规则

审计要覆盖时间变更、身份文件、网络环境、登录事件、特权命令与删除事件六类。规则追加到审计规则文件末尾：

R=/etc/audit/rules.d/audit.rules
sed -i '$ a\ -a always,exit -F arch=b64 -S adjtimex -S settimeofday -k time-change' $R
sed -i '$ a\ -a always,exit -F arch=b32 -S adjtimex -S settimeofday -S stime -k time-change' $R
sed -i '$ a\ -a always,exit -F arch=b64 -S clock_settime -k time-change' $R
sed -i '$ a\ -w /etc/localtime -p wa -k time-change' $R

sed -i '$ a\ -w /etc/group -p wa -k identity' $R
sed -i '$ a\ -w /etc/shadow -p wa -k identity' $R
sed -i '$ a\ -w /etc/gshadow -p wa -k identity' $R

sed -i '$ a\ -a always,exit -F arch=b64 -S sethostname -S setdomainname -k system-locale' $R
sed -i '$ a\ -w /etc/hosts -p wa -k system-locale' $R
sed -i '$ a\ -w /etc/sysconfig/network -p wa -k system-locale' $R

sed -i '$ a\ -w /var/log/lastlog -p wa -k logins' $R
sed -i '$ a\ -w /var/run/faillock/ -p wa -k logins' $R

sed -i '$ a\ -a always,exit -F arch=b64 -S unlink -S unlinkat -S rename -S renameat -k delete' $R

几个容易踩的点：sed '$ a' 只是在“最后一行之后”追加，空文件没有最后一行，因此第一条必须手工写入或用 printf >> 打底，后续才能继续追加；身份审计还应对口令与组口令记录文件以及账户清单文件各补一条；特权命令审计可以用 find 找出带 SUID/SGID 的可执行文件，把路径拼成 -a always,exit -F path=... -F perm=x -k privileged 形式的规则。规则追加后需要重启 auditd 乃至整机才能生效，不要在业务高峰期做。

第四步：日志与计划任务

回收日志文件权限，收紧 crontab 与 cron 目录，并改用白名单控制谁能创建计划任务：

find /var/log -type f -exec chmod g-wx,o-rwx {} +
chown root:root /etc/crontab; chmod og-rwx /etc/crontab
chown root:root /etc/cron.hourly; chmod og-rwx /etc/cron.hourly
rm -f /etc/cron.deny /etc/at.deny
touch /etc/cron.allow /etc/at.allow
chmod og-rwx /etc/cron.allow /etc/at.allow

可选地增加一份独立的操作留痕日志，记录执行时间、来源终端与命令内容：

echo 'export HISTORY_FILE=/var/log/useraudit.log' >> /etc/profile
echo 'export PROMPT_COMMAND="date \"+%F %T\" >> \$HISTORY_FILE; who am i >> \$HISTORY_FILE; history 1 >> \$HISTORY_FILE"' >> /etc/profile

第五步：SSH 与认证策略

SSH 侧的核心是关闭旧协议、限制尝试次数、禁用图形转发与空口令登录：

S=/etc/ssh/sshd_config
sed -i '$ a\ Protocol 2' $S
sed -i '$ a\ Port 42222' $S
sed -i '$ a\ LogLevel INFO' $S
sed -i -e '/X11Forwarding/ s/^/#/' $S
sed -i '$ a\ X11Forwarding no' $S
sed -i -e '/MaxAuthTries/ s/^/#/' $S
sed -i '$ a\ MaxAuthTries 6' $S
sed -i -e '/IgnoreRhosts/ s/^/#/' $S
sed -i '$ a\ IgnoreRhosts yes' $S
sshd -t && systemctl restart sshd

改端口之前，先确认防火墙与云侧安全组已放通新端口，并保留一个已登录会话，避免把自己锁在门外。

认证策略分两块：口令复杂度写进质量配置文件，登录失败锁定写进 PAM 栈：

P=/etc/security/pwquality.conf
sed -i -e '/minlen/ s/^/#/' $P;     sed -i '$ a\ minlen = 12' $P
sed -i -e '/dcredit/ s/^/#/' $P;    sed -i '$ a\ dcredit = -1' $P
sed -i -e '/ucredit/ s/^/#/' $P;    sed -i '$ a\ ucredit = -1' $P
sed -i -e '/ocredit/ s/^/#/' $P;    sed -i '$ a\ ocredit = -1' $P
sed -i -e '/lcredit/ s/^/#/' $P;    sed -i '$ a\ lcredit = -1' $P

A=/etc/pam.d/system-auth
sed -i '$ a\ auth required pam_faillock.so preauth audit silent deny=5 unlock_time=900' $A
sed -i '$ a\ auth [default=die] pam_faillock.so authfail audit deny=5 unlock_time=900' $A
sed -i '$ a\ auth sufficient pam_faillock.so authsucc audit deny=5 unlock_time=900' $A

口令质量模块本身要在 PAM 栈里被引用，参数为 try_first_pass retry=3；限制口令重用时，在 pam_unix.so 的策略行末尾追加 remember=5。同一目录下的同源 PAM 栈文件必须同步修改，否则两条登录路径会出现策略不一致。

第六步：账号与默认权限

清理不再使用的默认账号与用户组，把服务账号的 shell 设为不可登录，收紧家目录权限，最后统一默认 umask：

for u in adm lp sync shutdown halt news uucp operator games gopher ftp; do
  userdel "$u" 2>/dev/null
done
for g in adm lp news uucp games dip ftp floppy audio; do
  groupdel "$g" 2>/dev/null
done

usermod -s /sbin/nologin <服务账号>
chmod 750 /home/opsuser

sed -i '$ a\ TMOUT=1800' /etc/profile
sed -i '$ a\ HISTSIZE=30' /etc/profile
sed -i '$ a\ HISTTIMEFORMAT="%F %T `whoami` "' /etc/profile
sed -i '$ a\ umask 027' /etc/profile
sed -i '$ a\ umask 027' /etc/bashrc

SUID/SGID 的回收要挑对象：find / -perm /7000 列出全部候选后，对确实不需要提权的程序执行 chmod a-s。注意 ping、mount 这类程序去掉 SUID 后普通用户会失效，若业务依赖就先保留并在基线里登记为例外。

验证

逐条重跑清单中的检查命令，重点确认三件事：审计规则已加载（重启后用 auditctl -l 核对关键字）、SSH 新配置通过语法检查并能正常登录、口令策略对新建账号生效。建议用一台测试机完整跑一遍脚本，再推到存量机器。

风险与回滚

最高风险是 SSH 配置把运维人员锁在门外：改动前保留活跃会话、先 sshd -t 校验、确认端口放通，三条缺一不可。其次是 PAM 改错导致无法登录，处理方式是提前留一个 root 会话，必要时通过单用户模式恢复。

审计规则与内核参数改动需要重启才完全生效，重启前确认业务窗口。回滚直接取备份文件覆盖，再重启对应服务：

cp -a $BK/sshd_config /etc/ssh/sshd_config && systemctl restart sshd

常见问题

  • 审计规则重启后没生效：确认规则写在 audit.rules 而不是运行时列表，并检查文件末尾是否因换行问题被截断。
  • sed 追加没有效果：目标是空文件时 $ a 无的放矢，先写入一行占位内容再追加。
  • 改完 SSH 连不上：多数是防火墙或安全组未放通新端口，或 PAM 策略把 root 锁了，用控制台登录恢复。
  • ping 报权限不足：SUID 被回收所致，属于预期影响，按需在白名单中恢复。
  • 部分检查项在精简系统上不存在：例如没有邮件服务、没有 securetty 文件，属于不适用项，在基线记录里标注即可，不要为了“打勾”而安装多余软件包。
