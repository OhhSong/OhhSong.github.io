Ubuntu 22.04 安装 NVIDIA 驱动与 CUDA 11.8

从驱动匹配、屏蔽 nouveau 到直通显卡与验证，讲清 Ubuntu 装 CUDA 的顺序。

2026年10月21日 6 分钟阅读 运维手册 UbuntuNVIDIACUDA 操作系统与安全基线

一句话定位

在虚拟化平台上给虚拟机直通一块显卡并装好 CUDA，难点不在命令，而在顺序与版本：驱动和 toolkit 要匹配，nouveau 要先让位，PCI 设备要在关机状态下添加，最后才是环境变量与验证。顺序乱一步，后面所有报错都会指向错误的方向。

适用场景

  • 新建 GPU 虚拟机（推理、训练、图形计算）的初始化；
  • 已有 Ubuntu 节点补装驱动或升级 CUDA；
  • 从旧版本迁移，需要确认驱动下限与 toolkit 对应关系；
  • 排障：nvidia-smi 报错、nvcc 版本不符、驱动被自动升级。

前置条件

  • Ubuntu 22.04 LTS，正常安装而非最小化，内核与头文件版本一致；
  • 能访问软件源（公网或内网镜像），有 gcc、make 与当前内核头文件；
  • 虚拟化平台支持 PCI 直通（DirectPath I/O 一类），有停机窗口；
  • 已确认 Secure Boot 状态：开启时第三方驱动需签名，否则加载失败；
  • 记录当前驱动与 CUDA 版本，便于回滚。

操作步骤

动手前先留一份现场记录：uname -r、lsmod | grep nvidia、dpkg -l | grep nvidia、nvidia-smi -q 的输出各存一份。这不只是留档——升级失败时，对比新旧输出能快速判断是驱动没装、模块没加载，还是设备没直通，比从头猜省时间。

第一步：先确认版本匹配

驱动能支持的 CUDA 上限是硬约束，先对表再动手：

驱动分支可支持的最高 CUDA典型用途
47011.4老卡、旧平台兼容
52512.0本文基线，搭配 CUDA 11.8
53512.2新版仓库默认会升到这里

三个容易混淆的点：nvidia-smi 右上角的 CUDA Version 是驱动支持的最高运行时版本，不是已安装的 toolkit 版本；CUDA 11.8 要求驱动不低于 520.61.05，525 满足；toolkit 的 runfile 自带一个驱动（例如 520.61.05），只装 toolkit、不勾驱动，才不会覆盖已装好的版本。

lspci | grep -i nvidia
uname -r
gcc --version
apt-cache policy nvidia-driver-525

还要留意 CUDA 的小版本兼容性：同一主版本内（如 11.x），用较高版本驱动运行较低版本 toolkit 编译的程序通常没问题，反向则不行；跨主版本（11 升 12）一般要重装 toolkit 并重新编译依赖库。生产环境按业务框架官方支持的组合选，别追最新。

第二步：屏蔽 nouveau

开源 nouveau 与官方驱动互斥。不先禁用就装驱动，常见结果是设备被占用、模块加载失败，甚至装完重启黑屏。写入黑名单并更新 initramfs，重启后确认模块没被加载：

cat > /etc/modprobe.d/blacklist-nouveau.conf <<'EOF'
blacklist nouveau
options nouveau modeset=0
EOF
update-initramfs -u
reboot
lsmod | grep nouveau

lsmod 无输出才算成功。带图形界面的机器重启后分辨率可能变低，这是预期现象，装完驱动会恢复。

第三步：安装驱动

先补编译依赖与当前内核头文件，DKMS 编译模块时需要：

sudo apt-get update
sudo apt-get install -y gcc make linux-headers-$(uname -r)

再用官方 deb 仓库安装。包名与路径按实际下载的版本替换，先注册仓库，再交给 apt 装：

sudo dpkg -i nvidia-driver-local-repo-ubuntu2204-525.147.05_1.0-1_amd64.deb
sudo cp /var/nvidia-driver-local-repo-ubuntu2204-525.147.05/nvidia-driver-local-*-keyring.gpg /usr/share/keyrings/
sudo apt-get update
sudo apt-get install -y nvidia-driver-525

apt 解析依赖时可能把驱动升到更新的分支，例如从 525 升到 535。业务对版本敏感时显式锁定：

sudo apt-get install -y nvidia-driver-525=525.147.05-0ubuntu1
sudo apt-mark hold nvidia-driver-525

deb 仓库方式的好处是驱动与依赖交给 apt 管，升级、卸载都干净；代价是容易被仓库里的新版本带走。runfile 自带的驱动安装器适合离线环境，但版本升级要手动处理。两种方式不要混用，混装过一次就很难查清版本来源。

装完先别急着重启，用 dkms status 确认模块编译成功。Secure Boot 开启时模块会进入待签名队列，需要用 MOK 完成登记，否则重启后驱动不会加载。

第四步：添加 PCI 直通设备

虚拟机没有直通设备时，nvidia-smi 必然找不到卡。顺序是固定的：关机、编辑虚拟机设置、添加 PCI 设备、选择对应显卡的直通模式（不是共享或 vGPU）、开机。进入系统后确认设备与驱动：

lspci -nn | grep -i nvidia
nvidia-smi

直通后显卡被这台虚拟机独占，宿主机与其他虚拟机不能再用；热迁移通常也不支持。规划时把这两条写进变更说明，别等迁移窗口才发现迁不动。

第五步：安装 CUDA toolkit

安装包从官方下载页获取，或提前传入内网文件服务器。runfile 方式最可控：TUI 中接受许可、取消 Driver 勾选、只保留 Toolkit，实测全选组件容易在依赖上失败：

chmod 755 cuda_11.8.0_520.61.05_linux.run
sudo ./cuda_11.8.0_520.61.05_linux.run

无人值守场景用参数跳过交互：

sudo ./cuda_11.8.0_520.61.05_linux.run --silent --toolkit --toolkitpath=/usr/local/cuda-11.8

第六步：配置环境变量

装完 nvcc 不在 PATH 里，直接执行会报找不到命令。写进全局 profile，所有用户都能用：

cat >> /etc/profile.d/cuda.sh <<'EOF'
export PATH=/usr/local/cuda-11.8/bin:$PATH
export LD_LIBRARY_PATH=/usr/local/cuda-11.8/lib64:$LD_LIBRARY_PATH
EOF
source /etc/profile.d/cuda.sh

环境变量只对登录 shell 生效。systemd 托管的服务、容器或 cron 启动的进程读不到 /etc/profile.d，这类场景要把库路径写进 /etc/ld.so.conf.d/cuda.conf 再执行 ldconfig，否则运行时会报找不到 libcudart 一类错误。

多版本共存时，用 update-alternatives 或让 /usr/local/cuda 软链指向当前版本，比反复调 PATH 顺序更直观，也不容易在新开终端里失效。

验证

三件事依次确认：nvidia-smi 能看到卡、驱动版本与显存；nvcc --version 输出 11.8；编译一个小样例能跑通。业务侧再用框架自检：

nvidia-smi --query-gpu=name,driver_version,memory.total --format=csv
nvcc --version
cat /usr/local/cuda/version.json

框架装对应 CUDA 版本的 wheel（例如 cu118），不要用 CPU 版轮子验证 GPU；torch.cuda.is_available() 返回 True 才算链路打通。只看 nvcc 版本而不跑一次实际运算，很容易漏掉库路径问题。最后跑一次小矩阵乘法或框架自带的基准，确认算力正常、显存可分配，避免”能识别但一跑就崩”的情况。

风险与回滚

风险按概率排：内核升级后 DKMS 编译失败；nouveau 未屏蔽导致设备被占用；apt 把 525 升到 535，与业务锁定的 CUDA 版本不再匹配；直通显卡让虚拟机失去热迁移能力。回滚顺序是先卸驱动与 toolkit，再清配置：

sudo apt-mark unhold nvidia-driver-525
sudo apt-get purge -y '^nvidia-.*' '^cuda-.*'
sudo rm -rf /usr/local/cuda-11.8 /etc/profile.d/cuda.sh
sudo update-initramfs -u
reboot

重装前把 /etc/modprobe.d/blacklist-nouveau.conf 一并清理，避免下次安装时误以为已经屏蔽、结果顺序又乱掉。

常见问题

  • nvidia-smi 报 No devices were found：PCI 设备没加或加错，关机重新添加直通显卡。
  • 驱动版本和装的不一样：apt 跟随仓库升级了，用 apt-cache policy 看候选版本并 hold。
  • nvcc 找不到：PATH 没生效，确认 profile 被 source，且文件有可执行权限。
  • DKMS 编译失败：内核头文件缺失或内核刚升级，装 linux-headers-$(uname -r) 后重跑。
  • 重启后黑屏或循环登录：nouveau 与官方驱动冲突，或 Secure Boot 未签名，先卸驱动回到开源显卡。
  • 内核升级后驱动失效：DKMS 需要按新内核重新编译，装好新内核头文件后重跑 dkms autoinstall，或重装同版本驱动。
  • 安装过程提示需要重启：安装器检测到内核模块变化，按提示重启，重启后再确认驱动加载。
  • CUDA 版本与框架不匹配：按框架要求装对应 wheel，主版本不要混用。
