VMware 到 SmartX 的在线迁移实施要点

以迁移工具为主线，梳理站点对接、网络放通与迁移后网络修正的关键动作。

2026年10月21日 5 分钟阅读 运维手册 VMwareSmartX迁移 虚拟化与超融合

一句话定位

跨平台迁移的难点不在点“开始”，而在网络策略、驱动适配和迁移后的网络修正——把这三件事前置，迁移就只是一批可回退的任务。

适用场景

  • 虚拟化平台整体替换，需要把存量虚拟机从 VMware 迁到 SmartX；
  • 只迁移部分业务系统，源端虚拟机仍保留运行；
  • 需要在正式迁移前做小批量预演与回退验证；
  • 迁移后虚拟机网卡 MAC 变化，需要修正客户机网络配置。

前置条件

  1. 迁移工具：迁移工具已部署并同时对接源 vCenter 与目标平台，管理入口形如 https://migrate.example.com，仅对跳板机开放访问。
  2. 网络策略：迁移工具到源 vCenter、源 ESXi 节点、目标平台各节点的端口全部放通，尤其是 ESXi 的 902 端口与目标端的存储访问端口。
  3. 账号权限：源端准备只读加迁移所需权限的账号，目标端准备具备建机与存储映射权限的账号。
  4. 容量与备份：目标端存储容量覆盖源端已用空间并留余量；迁移前对关键业务做备份或快照。
  5. 窗口与清单：明确迁移批次、每批虚拟机清单、依赖关系与回退顺序，在业务低峰执行。

操作步骤

第一步：打通网络策略

迁移工具需要同时访问三侧，端口按用途逐条确认：

目标端口用途
源 vCenter443、80读取清单与虚拟机信息
源 ESXi 节点902数据传输通道
目标平台 VIP443、80管理接口
目标平台各节点860、3260、3261存储与数据通道
目标平台各节点10200–10207迁移数据通道

源虚拟机分散在不同宿主机时，每台宿主机所在节点都必须放通 902，只放通一台会在任务里报通信不可达。

第二步：建立站点对

首次迁移需要分别添加源站点与目标站点：在迁移工具中录入 vCenter 地址与凭据，选择目标平台的接入地址与凭据，校验连通性后保存。站点对建立成功后，工具侧会同步两端的集群、主机、存储与网络清单，后续任务的资源映射都以这份清单为准。

# 连通性自检，建议在迁移工具所在网段执行
curl -k -s -o /dev/null -w "%{http_code}\n" https://vcenter-01.example.com
nc -zv 192.0.2.11 902
nc -zv 192.0.2.20 3260

第三步：源端预演克隆

正式迁移前，先在源端克隆一台代表性虚拟机做预演。克隆出来的虚拟机要断网启动，重点核对三件事：网卡是否被识别、MAC 是否变化、路由与 DNS 是否正常。Linux 客户机常见的情况是网卡名从 eth0 变成 ens192，配置文件里仍绑着旧 MAC：

# 查看新网卡名与 MAC
ip link show
ip addr show

# 修改网卡配置中的 MAC 与设备名
vi /etc/sysconfig/network-scripts/ifcfg-ens192

# 使配置生效
nmcli connection reload
systemctl restart network
ip addr show

预演通过后再创建正式迁移任务，避免把问题带到生产批次。

第四步：创建并执行迁移任务

任务向导按顺序选择：源端虚拟机、目标端集群与存储、网络映射、迁移方式。提交后工具会先做一次预检，检查源端快照、磁盘类型、客户机操作系统与目标端兼容性。预检不通过时按提示处理，常见原因是源端存在快照链、磁盘为独立模式或目标存储容量不足。

若任务报源端 ESXi 的 902 端口不可达，两条路可选：申请网络策略放通该节点；或先把虚拟机热迁移到已放通策略的宿主机上，再重新提交任务。批量迁移时建议按批次串行，单批控制在可控数量内，便于失败时快速止损。

# 迁移前核对源虚拟机电源状态与所在宿主机
# 任务列表里逐台确认进度、速率与失败原因
# 失败任务先看错误码，再决定重试还是回退

第五步：迁移后修正网络并安装工具

虚拟机在目标平台首次启动后，网卡 MAC 大概率变化，需要按预演时的方式修正客户机配置，确保 IP、网关、DNS 与迁移前一致。业务验证通过后，在客户机内安装目标平台的虚拟机工具，用于上报 IP、主机名等基础信息，平台侧才能正确展示虚拟机详情。

# 安装完成后确认服务状态
systemctl status smtx-tools

# 若服务名不同，以实际安装包为准，按对应平台文档执行

验证

  1. 迁移任务状态为成功，无部分完成或超时残留；
  2. 虚拟机在目标平台可正常开机，控制台可登录；
  3. 客户机内 IP、网关、DNS、主机名与迁移前一致，业务端口可访问；
  4. 从堡垒机按原地址登录验证，应用侧连接与依赖正常；
  5. 目标平台页面能看到虚拟机的 IP 与主机名，监控采集恢复。

风险与回滚

  • 源端仍在运行：迁移完成不等于可以立即删除源端，先并行观察一个业务周期，确认无回退需求后再清理。
  • MAC 与授权绑定：依赖 MAC 授权的软件在迁移后会失效，提前梳理授权方式，改为按主机名或硬件指纹绑定。
  • 迁移期间源端变更：任务执行中不要在源端改配置或扩容磁盘，否则需要重新同步甚至重做。
  • 回滚：保留源端虚拟机不删除，回滚时关闭目标端虚拟机、恢复源端开机并核对网络，再按原路径切回。
  • 网络策略遗漏：分批迁移时容易只放通部分节点，任务提交前按宿主机清单逐台核对。

常见问题

Q：任务提示 902 端口通信不可达。 源虚拟机所在宿主机未放通策略。补策略，或先把虚拟机热迁移到已放通的节点再重试。

Q：迁移后虚拟机网络不通。 先看客户机内网卡是否识别、MAC 与配置文件是否一致，再看目标平台端口组 VLAN 是否与源端一致。

Q：平台页面看不到虚拟机 IP。 多为未安装虚拟机工具或工具服务未启动，安装并启动后等待一个采集周期。

Q：迁移速度远低于预期。 检查数据通道带宽是否被其他任务占用、源端存储是否达到 IO 上限，必要时降低并发任务数。

Q：预检提示源端存在快照。 先合并或删除快照再迁移。快照链会让数据同步变慢，也容易造成迁移后的磁盘一致性问题。
