Zabbix 监控与告警配置手册

从服务端、代理端到客户端接入的完整配置路径，含中间件监控标准与告警通知要点。

2025年9月18日 7 分钟阅读 运维手册 Zabbix监控告警 监控与告警

一句话定位

Zabbix 把指标采集、时序存储、阈值判断和通知投递串成一条闭环。本文把服务端部署、代理端分区采集、客户端接入、中间件监控标准和告警维护整合成一条可复制的操作路径，读完应当能独立搭起一套覆盖机房与云上环境的中等规模监控体系。

适用场景

  • 需要统一纳管物理机、虚拟机和云主机的基础资源指标，替代分散的脚本巡检。
  • 需要对 MySQL、PostgreSQL、Redis、MongoDB、Nginx、Tomcat 等中间件做可用性与性能探活。
  • 采集点分散在多个网络区域，不希望所有采集流量都汇聚到中心机房链路上。
  • 需要按业务重要级别分层通知：一般故障走消息通道，核心故障升级为语音呼叫。

架构与原理

整套平台由三层构成。

数据层：一台独立的数据库节点承载配置、历史和趋势数据，MySQL 8 是常见选择，字符集用 utf8，排序规则用 utf8_bin 以区分大小写。

服务层：一台应用节点运行 server 进程与 Web 前端。server 负责调度采集、计算触发器、生成事件并投递动作；Nginx 加 PHP-FPM 只承担页面渲染与 API 请求。

采集层：每个网络区域部署一台 proxy，代理下属主机的数据采集与缓冲，再按秒级间隔汇总回 server。proxy 在本地落库，链路中断期间数据不会立刻丢失，恢复后补传。主机侧安装 agent 或 agent2，被动模式下由 server 或 proxy 主动取数，主动模式则由客户端定时上报。

这样的分层带来的直接好处是：新增机房时只需加一台 proxy 和对应网络策略，中心节点的连接数不会线性膨胀。

前置条件

项目要求
服务器应用节点 8 核 16G 起，数据库节点按监控主机数评估，建议 SSD
系统CentOS 7.9 / 8.x 或同源发行版，时区统一为 Asia/Shanghai
端口agent 被动取数 10050/TCP，server 与 proxy 通信 10051/TCP，JMX 10052/TCP
网络proxy 到数据库、server 双向可达；proxy 到被监控主机的采集端口放行
依赖Nginx、PHP-FPM、数据库客户端、JMX 网关所需的 Java 运行环境
规范主机名与业务系统、环境一一对应，后续靠主机名做分组与告警路由

监控端代理的部署位置要提前和网络侧对齐，否则后补策略会让接入周期拉长。命令中的地址、库名、账号均为占位符，执行前替换为目标环境的实际值。

操作步骤

1. 初始化数据库

在数据库节点上安装 MySQL，启动并设为开机自启，用日志里的临时口令完成首次登录后立刻改掉，随后建库与授权。

CREATE DATABASE zabbix CHARACTER SET utf8 COLLATE utf8_bin;
CREATE USER 'zabbix'@'localhost' IDENTIFIED BY '<db-pass-here>';
GRANT ALL PRIVILEGES ON zabbix.* TO 'zabbix'@'localhost';

导入官方初始表结构，注意数据包体量较大，用 zcat 管道直接灌入可以省一次落盘。

SCHEMA=$(rpm -ql zabbix-sql-scripts | grep 'create.sql.gz$')
zcat "$SCHEMA" | mysql -uzabbix -p zabbix

2. 安装并调优 server

先装软件源，再安装服务端、前端、SQL 脚本和 agent。参数调整写在配置文件末尾，覆盖默认值。

# /etc/zabbix/zabbix_server.conf 片段
DebugLevel=3
Timeout=15
CacheSize=256M
HistoryCacheSize=512M
HistoryIndexCacheSize=256M
TrendCacheSize=256M
ValueCacheSize=256M
DBHost=192.0.2.20
DBPort=3306
DBName=zabbix
DBUser=zabbix
StartPollers=80
StartPollersUnreachable=15
StartTrappers=90
StartPingers=30
StartDiscoverers=8
StartHTTPPollers=10
StartProxyPollers=5

数据库连接口令不在本文件里明文出现，统一放进仅 root 可读的引用文件，或在安装后由部署脚本注入。参数按采集规模分批上调，一次把 Pollers 拉到几百只会把内存吃满。

调整内核参数后重启服务，并确认进程全部拉起。

systemctl restart zabbix-server
systemctl restart zabbix-agent nginx php-fpm
systemctl enable zabbix-server
systemctl enable zabbix-agent nginx php-fpm

3. 配置 Web 前端

修改 Nginx 站点配置，把 server_name 指向对外地址，静态资源与 PHP 请求分开处理，随后在浏览器打开 http://192.0.2.10/ 完成初始化向导：选择 MySQL、填库地址与账号、设置时区，最后用默认管理员登录并立刻改口令。

4. 部署 proxy

proxy 的版本必须与 server 主版本一致，否则上报会被拒绝。安装 proxy 与 Java 网关后，在配置里写明自身主机名、server 地址和本地库信息，并把 ProxyMode 设为主动模式，让 proxy 主动向 server 拉取配置。

# /etc/zabbix/zabbix_proxy.conf 片段
Server=192.0.2.10
Hostname=proxy-a
ProxyMode=0
DBName=zabbix_proxy
DBPort=3306
DBUser=zabbix
JavaGateway=192.0.2.30
JavaGatewayPort=10052
StartJavaPollers=5

5. 客户端接入

Linux 优先用 agent2，单包集成了多数中间件的原生采集插件。

rpm -Uvh zabbix-release-5.4-1.el8.noarch.rpm
dnf clean all
dnf install -y zabbix-agent2
# 编辑 /etc/zabbix/zabbix_agent2.conf，改写 Server、ServerActive、Hostname
systemctl enable --now zabbix-agent2
firewall-cmd --permanent --add-port=10050/tcp && firewall-cmd --reload

Windows 主机解压客户端包后把可执行文件与配置放到固定目录，配置中至少写明服务端地址与主机名，然后以管理员身份注册并启动服务。

Server=192.0.2.10
ServerActive=192.0.2.10
Hostname=node-01
LogFile=D:\zabbix\zabbix_agentd.log
D:\zabbix\zabbix_agentd.exe -i -c D:\zabbix\zabbix_agentd.win.conf
D:\zabbix\zabbix_agentd.exe -s -c D:\zabbix\zabbix_agentd.win.conf

主机名务必与平台登记的名字完全一致，这是排查“数据不上报”时第一个要核对的地方。

6. 监控对象接入标准

对象采集方式关键前置需要配置的宏
操作系统agent / agent210050 放行无
MySQLagent2 插件建只读监控账号并授权若干全局权限连接串、账号、口令
OracleODBC建监控用户、配 ACL、装 unixODBCDSN、账号、口令、端口
PostgreSQLagent2 插件建监控用户并改 pg_hba 信任策略账号、口令
Redisagent2 插件若有鉴权需提供口令口令
MongoDBagent2 插件建仅含 serverStatus 权限的角色连接串、账号、口令
Nginxstub_status编译含状态模块，location 限源地址状态页路径
TomcatJMX改启动参数暴露端口并关鉴权（限内网）端口
Apachemod_status开启状态页并限定来源状态页路径
Zookeeper端口探活管理端口放行端口
URL 探活Web 场景边缘 proxy 具备出网能力域名、期望状态码

数据库类监控要单独开最小权限账号，禁止复用业务账号；JMX 关闭鉴权只允许发生在受控内网，且必须有网络侧策略兜底。

7. 告警与报表

告警链路由三部分组成：触发器定义“什么算故障”，动作定义“发给谁、多久发一次”，媒介定义“走什么通道”。一般资源类告警走消息通道，核心链路告警叠加语音呼叫，语音脚本通过云通信接口外呼，接口凭证放在受控目录、由运行账号读取，不进版本库、不写进脚本。

日常报表采用截图加邮件的组合：定时任务先拉取问题列表页面并保存为静态页，再用无头浏览器整页截图，最后由脚本把图片作为附件发出。

59 5 * * * /opt/opsreport/render_problem_page.sh
1 6 * * * /opt/opsreport/send_problem_report.py

无头浏览器截图要装中文字体，否则图里全是方框；同时把页面的图表字体名改成已安装的中文字体。低配机器上没有独立显卡时，启动参数需要关掉沙箱与 GPU 相关选项。

8. 维护时间

计划内变更应先在平台上建立维护窗口，把目标主机与时间范围圈进去，窗口内的触发器不产生事件也不通知。窗口结束前确认变更已完成，避免遗漏后告警延迟爆发。

验证

  • zabbix_get -s 192.0.2.50 -k agent.ping 返回 1，说明采集链路通。
  • 前端主机列表中出现绿色可用性图标，最新数据里能看到 CPU、内存、磁盘的最新值。
  • proxy 列表显示最后可见时间持续更新，说明上报正常。
  • 数据库中间件类主机点开监控项，手动取值有数字返回，才算接入完成。
  • 人为触发一次测试告警，确认动作、媒介、接收人全链路可达。

风险与回滚

修改 server 参数需要重启进程，采集会中断一到两分钟，务必在业务低峰执行。升级前备份数据库与配置文件，保留旧版本安装包，异常时先回退二进制再恢复库。proxy 跨主版本升级要先升 server 再升 proxy。内核参数调整可能影响同机其他服务，改动前记录原值。数据库扩容、字符集调整属于不可逆操作，必须先做快照。

常见问题

页面中文变成问号或方框。 缺字体，安装中文字体包并在图形字体配置里指定字体名，重启 PHP-FPM。

主机可用性显示红色。 依次核对网络策略、agent 进程、超时时间、主机名是否与平台登记一致。

历史数据涨得很快。 缩短保留天数或按表分区，同时确认是否有低价值监控项在高频采集。

proxy 显示无数据。 检查两端口是否放行、版本是否一致、proxy 主机名是否与平台登记一致，以及本地库是否已初始化。

JMX 采不到数。 确认启动参数里的主机名与端口、防火墙策略，以及 Java 网关是否在监听。

告警风暴。 给触发器加依赖，把底层资源故障的上层告警抑制掉，并对同类事件设置静默。
