vSphere Replication 跨 vCenter 容灾复制配置

从站点对建立到出站复制，说明 RPO、时间点实例与恢复演练的配置方法。

2025年7月18日 5 分钟阅读 运维手册 VMwarevSphere Replication容灾 备份、容灾与应急

一句话定位

vSphere Replication 用异步复制把虚拟机数据持续送到另一个 vCenter，配合站点对管理实现可编排的容灾恢复，核心参数只有两个：RPO 与保留的恢复点。

适用场景

  • 同城或异地机房之间需要虚拟机级容灾，RPO 允许分钟级；
  • 生产与容灾分属两个独立 vCenter，需要跨 VC 复制；
  • 需要对关键虚拟机保留多个时间点，支持恢复到故障前的某个时刻；
  • 迁移或割接前，需要临时复制一批虚拟机做兜底。

前置条件

  1. 组件就绪：两端 vCenter 已部署 vSphere Replication，版本与 vCenter 匹配，Site Recovery 模块可正常打开。
  2. 网络与时间：两端管理网络互通，vCenter 与 VR 设备时间同步；跨站点链路带宽满足复制速率。
  3. 容量：目标端数据存储容量覆盖源端虚拟机已用空间，并为时间点实例预留增量空间。
  4. 权限：两端具备 Site Recovery 管理与复制配置权限的账号。
  5. 策略：明确每类业务的 RPO 与保留点数，避免所有虚拟机套用同一档参数。

操作步骤

第一步：进入 Site Recovery 并建立站点对

# 管理入口示例
https://vcenter-01.example.com

# 左上角菜单 → Site Recovery → 打开 Site Recovery

跨 VC 复制必须新建站点对，配对类型选择与不同的 vCenter 配对，录入对端 vCenter 地址（IP 或域名均可），点击查找实例。首次连接会弹出证书告警，核对指纹后接受，再勾选需要启用的服务，提交后等待近期的站点对任务完成。

# 站点对建立后的自检项
# 1) 两端 VR 设备状态正常
# 2) 站点对显示已连接
# 3) 对端凭据校验通过

第二步：确认复制方向与目标资源

复制分出入两个方向：出站是从本 VC 复制到对端，入站是接收对端复制到本 VC。选择出站后新建复制任务，依次选择 VR 服务器（多台时可手工指定，否则自动分配）、待复制的虚拟机、目标端的数据存储。存储选择要考虑 IO 能力与容量，不要与生产业务争抢同一存储池的带宽。

第三步：配置 RPO 与时间点实例

RPO 是最大可容忍的数据丢失量，也就是两次同步之间允许丢失的时间跨度。RPO 越小，复制越频繁，链路带宽与源端快照开销越大；把 RPO 压到分钟级以下之前，先算清链路余量。

时间点实例用于保留多个历史恢复点：每日实例数乘以保留天数，再加最近一份。例如每天三个实例、保留五天，就有十六份可恢复点，恢复时以快照形式呈现，可手工选择恢复到任一时刻。实例越多，目标端占用的增量空间越大。

数据压缩与加密能降低带宽消耗，但会消耗目标端的 CPU，在目标端资源紧张时谨慎开启。

# 配置项核对
# RPO：按业务容忍度设置，常见 15 分钟到 4 小时
# 时间点实例：每日实例数 × 保留天数 + 1
# 压缩与加密：目标端 CPU 有余量时再开启

第四步：初始化同步与状态确认

任务提交后先做全量初始化同步，同步期间源端虚拟机会产生一次快照，磁盘越大耗时越长。初始化完成后进入增量复制周期，每次按 RPO 节奏同步变化块。

# 复制状态检查点
# 1) 复制任务状态为正常，无错误告警
# 2) 最近一次同步时间与 RPO 匹配
# 3) 目标端虚拟机处于占位状态，未开机

第五步：恢复演练

容灾配置完不等于可用，必须做恢复演练。演练在隔离网络中进行，用测试恢复把目标端虚拟机拉起到不冲突的网段，核对系统启动、数据完整性与应用端口；确认无误后删除测试虚拟机，不影响正式复制关系。正式切换时才执行恢复，恢复后需要按目标端网段修正 IP 与 DNS。

验证

  1. 站点对状态为已连接，两端 VR 设备无告警；
  2. 复制任务状态正常，最近同步时间在 RPO 窗口内；
  3. 目标端占位虚拟机与源端配置一致，磁盘容量匹配；
  4. 测试恢复可成功启动，应用在隔离网段内可访问；
  5. 时间点实例数量与配置一致，能选择到预期时刻的恢复点。

风险与回滚

  • RPO 不达标：链路带宽不足或增量过大时，复制会持续滞后，需要扩容链路或调整 RPO。
  • 快照开销：初始化与每次同步都可能产生快照，异常时会在源端堆积快照，必须纳入日常巡检。
  • 目标容量耗尽：时间点实例与增量数据会持续增长，容量告警要提前处理，否则复制中断。
  • 证书与时间：证书过期或时间偏差会导致站点对断开，续期与校时纳入例行维护。
  • 演练污染生产：测试恢复必须使用隔离网络与独立存储，禁止直接在生产网段拉起目标虚拟机。
  • 回滚：删除复制关系不影响源端虚拟机；若要停止容灾，先在源端确认无恢复需求，再删除复制并清理目标端占位机。

常见问题

Q：站点对建立失败。 依次核对版本兼容性、两端时间同步、证书是否被接受、管理网络端口是否放通。

Q：复制任务正常但 RPO 一直不达标。 看链路带宽与增量速率，再看源端存储是否成为瓶颈；必要时降低同步频率或对非关键虚拟机调整策略。

Q：初始化同步特别慢。 首次全量传输受链路与磁盘读性能双重限制，可在窗口内错峰执行，避免与其他批量任务并发。

Q：恢复后虚拟机网络不通。 目标端网段与源端通常不同，恢复后需要修改 IP、网关与 DNS；演练时同样要改，不要直接沿用生产地址。

Q：时间点实例占空间过快。 减少每日实例数或缩短保留天数，同时确认增量变化率是否异常升高。
